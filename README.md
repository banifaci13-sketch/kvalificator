# Ассистент агентства Soroka Marketing

Рабочее место агентства: презентации, КП и отчёты в фирменном стиле, медиапланы, задачи команды по клиентам — и квалификатор заявок с сайта.

| Раздел | Что делает |
| --- | --- |
| **Документы** | КП, медиапланы, отчёты и стратегии из шаблонов; редактор слайдов с живым превью, проверка перед выгрузкой, PPTX / PDF / HTML |
| **Шаблоны** | Встроенные и свои шаблоны презентаций; свой — из любого документа |
| **Медиапланы** | Расчёт по каналам (CPC/CPM → показы, клики, лиды, CPL), комиссия, НДС, ДРР, сценарии; Excel с формулами и слайды в презентацию |
| **Задачи** | Как в YouGile: проекты (клиенты и «Общие задачи») → доски → свои колонки; стикеры срока, ответственного и важности |
| **Календарь** | Встречи команды, напоминания и план на день в Telegram, ссылки Zoom и Телемост одной кнопкой, подписка в Яндекс/Google календаре |
| **ИИ-помощник** | Черновик презентации по брифу и заявке, правка слайдов; цифр не придумывает, данные клиента в модель не уходят |
| **Квалификатор** | Виджет на сайте и Telegram-бот, оценка заявок 1–5, воронка и сводка |

## Квалификатор

Виджет-квалификатор для сайта: задаёт вопросы из таблицы «Вопросы при первом общении», оценивает лида по шкале 1–5 из таблицы «Этапы продаж» и отправляет карточку менеджерам в Telegram (и/или в CRM).

Ядро квалификации не зависит от канала: к нему подключены виджет и Telegram-бот, следующим — бот в MAX.

```
 сайт (WordPress)          сервер квалификатора                    менеджеры
┌──────────────┐   HTTP   ┌──────────────────────────────┐   ┌──────────────────┐
│ widget.js    │ ───────▶ │ сценарий → движок → оценка   │ ─▶│ Telegram-чат     │
└──────────────┘          │ SQLite (лиды, сессии)        │ ─▶│ CRM (вебхук)     │
 Telegram, MAX ─────────▶└──────────────────────────────┘   └──────────────────┘
```

## Что умеет

- **Диалог в виджете.** Вопросы по одному, варианты кнопками, необязательные можно пропустить. Есть прогресс-бар и согласие на обработку ПДн со ссылкой на политику. Контакт проверяется: телефон, e-mail или @telegram.
- **Ветвления.** Например, «С кем взаимодействовать?» задаётся, только если решение принимает не собеседник. «Чем недовольны?» — только если уже работали с агентством.
- **Оценка 1–5 с объяснением.** Менеджер видит, за что начислены баллы:
  - 5 — звёздный бренд или бюджет от 1 млн с сильными сигналами;
  - 4 — бюджет от 300 тыс., приоритетная сфера;
  - 3 — адекватная компания;
  - 2 — «важна только цена», маленький бюджет, нет доступа к ЛПР;
  - 1 — стоп-слова или спам.

  Правила лежат в `config/scoring.json`.
- **Теги.** `#звёздный_бренд`, `#приоритетная_сфера`, `#зарубежный`, `#B2B`, `#партнёр_Юнистрим`, `#важна_цена`, `#нет_доступа_к_ЛПР`.
- **Разный ответ клиенту по рейтингу.** Для 4–5 — «руководитель свяжется в течение 30 минут». Для 2 — ориентир по бюджету из `budgetHints`, если он заполнен. Сам рейтинг клиенту не показывается.
- **Продолжение после перезагрузки страницы.** Диалог восстанавливается с того же места.
- **UTM-метки, страница и реферер** попадают в карточку лида.
- **Цели Яндекс.Метрики:**
  - `kval_open`, `kval_start`;
  - `kval_step_<id вопроса>` — по ним виден, на каком вопросе уходят;
  - `kval_lead`, `kval_handoff`.
- **Надёжная доставка.** Если Telegram или CRM недоступны, лид досылается каждые 5 минут, без дублей.
- **Вопросы можно вести в Google Таблице.** Менеджер правит вопросы без программиста, сервер подхватывает изменения в течение 5 минут.

## Быстрый старт

Нужен Node.js 22.13+.

```bash
npm install
cp .env.example .env      # заполнить
npm start                 # http://localhost:3000/demo.html — демо-страница
npm test
```

## Установка на сайт

**WordPress.**

1. Заархивируйте папку `wordpress/soroka-kvalificator` в zip.
2. Загрузите архив в «Плагины → Добавить новый → Загрузить плагин» и активируйте.
3. В «Настройки → Квалификатор» укажите адрес сервера. Там же задаются текст кнопки, цвета, номер счётчика Метрики и страницы-исключения.

**Любой другой сайт** — одна строка перед `</body>`:

```html
<script src="https://kval.soroka-marketing.ru/widget.js" defer data-metrika="12345678"></script>
```

Открыть виджет из своей кнопки:
- ссылка `<a href="#kvalificator">`;
- атрибут `data-kval-open`;
- вызов `window.SorokaKval.open()`.

## Уведомления менеджерам

1. Создайте бота у [@BotFather](https://t.me/BotFather) и добавьте его в чат менеджеров.
2. В `.env` укажите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_MANAGER_CHAT_ID`. Id чата можно узнать, например, через @getidsbot; у групп он начинается с `-100`.
3. Для CRM укажите `LEAD_WEBHOOK_URL`. Лид уходит JSON-ом, подпись HMAC-SHA256 передаётся в заголовке `x-signature`, если задан `LEAD_WEBHOOK_SECRET`.

## Telegram-бот

Тот же опрос, что и в виджете, работает в личных сообщениях бота. Токен один — и для бота, и для уведомлений менеджерам.

- **Ответы.** Варианты — кнопками; выбранный вариант отмечается ✅ в сообщении. На текстовые вопросы клиент отвечает сообщением, необязательные можно пропустить кнопкой.
- **Контакт в одно нажатие.** Кнопки «📱 Поделиться номером» и `@username` клиента.
- **Продолжение из виджета.** Ссылка «Удобнее в мессенджере? Telegram» открывает бота с тем же опросом. Ответы, данные на сайте, и UTM-метки сохраняются.
- **Команды.** `/start` продолжает начатый опрос или начинает новый, `/restart` начинает заново.
- **Карточка лида в чате менеджеров** приходит с кнопкой «🙋 Взять в работу». Нажавший закрепляет лид за собой, остальные видят «Уже в работе: @имя».

Настройка: создайте бота у [@BotFather](https://t.me/BotFather), добавьте его в чат менеджеров и укажите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_MANAGER_CHAT_ID`. По умолчанию бот работает через long polling — дополнительной настройки не нужно. Для webhook задайте `TELEGRAM_WEBHOOK_URL`.

Если Telegram недоступен при запуске, сайт и виджет всё равно работают, а ошибка пишется в лог.

## Как проверить, что всё работает

1. **Автотесты** — `npm test`. Прогоняют опрос целиком через API виджета и через Telegram-бота (на имитации Telegram, без реального токена), оценку лидов, разбор Google Таблицы, доставку уведомлений.
2. **Проверка настроек** — `npm run check`. Проверяет вопросы и Google Таблицу, правила оценки, токен бота, доступ к чату менеджеров. Предупреждает о незаполненном. С флагом `npm run check -- --send-test` отправит тестовую карточку лида в чат менеджеров.
3. **Вручную.**
   - Запустите `npm start` и откройте `http://localhost:3000/demo.html`, пройдите опрос в виджете — карточка придёт в чат менеджеров.
   - Напишите боту `/start` и пройдите опрос в Telegram.
   - В виджете нажмите «Удобнее в мессенджере? Telegram» — опрос должен продолжиться в боте с того же вопроса.
   - Нажмите «Взять в работу» под карточкой.

## Вопросы в Google Таблице

1. Выполните `npm run scenario:csv` и импортируйте `config/scenario-template.csv` в Google Таблицу.
2. Колонки:
   - `id` — латиница, менять нельзя: на id завязаны правила оценки;
   - `название`;
   - `тип`: `choice`, `text`, `contact` или `consent`;
   - `вопрос`;
   - `варианты` — по одному в строке, в виде `value: Подпись`;
   - `обязательный` — `1`, если обязательный;
   - `показывать если` — например, `decision_maker=with_me,other`;
   - `подсказка`.
3. Опубликуйте таблицу: «Файл → Поделиться → Опубликовать в интернете → CSV». Ссылку укажите в `SCENARIO_CSV_URL`.

Если таблица заполнена с ошибкой, сервер продолжит работать на прежней версии вопросов и запишет причину в лог.

## Рабочее место

`https://ДОМЕН/` — открывается стартовый раздел сотрудника (по умолчанию «Документы»). Разделы — в тёмной панели слева (на телефоне — сверху). Внизу панели — быстрый выбор темы.

**Внешний вид** (щелчок по своему имени внизу панели → «Внешний вид») — у каждого свой: тема, цвет акцента (бирюзовый, синий, фиолетовый, зелёный, оранжевый, розовый, графит), фон кабинета (дымка, сияние, закат, ночь, точки или своё фото из медиатеки), плотность (обычная или компактная), боковая панель (с подписями или только значки), стартовый раздел. Настройки хранятся в профиле и действуют на любом устройстве; документы и презентации всегда в фирменных цветах. В редакторах документа и медиаплана панель сворачивается до значков, чтобы освободить место.

### Документы и шаблоны

- **Создать документ** — выбрать шаблон (КП, медиаплан, ежемесячный отчёт, стратегия или свой), при желании заявку клиента: клиент, услуга и задача подставятся из ответов квалификатора, дата и менеджер — автоматически. Из карточки лида — блок «Документы» → «Создать».
- **Редактор** — слева слайды (добавить, переставить, копия, удалить), в центре поля слайда, справа живое превью. Сохраняется само.
- **Проверить** — заполненность, заготовки `[заполнить…]` и `{{…}}`, источник и статус у цифр, переполнение текста, кегль, поля, контраст, логотип. С ошибками выгрузка не пройдёт; номер слайда в списке ошибок — ссылка на слайд. Администратор может скачать черновик с ошибками для внутреннего обсуждения.
- **Скачать** — PowerPoint (редактируемый: заголовки, таблицы и графики правятся в PowerPoint), PDF, HTML. История выгрузок хранится.
- **Шаблоны** — встроенные не меняются, правится копия. Свой шаблон: «Ещё» → «Сохранить как шаблон»; подстановки пишутся как `{{client}}`, `{{date}}`, `{{manager}}`.

### Медиапланы

- **Нормативы** — средние ставки, CTR и конверсия в лид по каналам из прошлых кампаний. Меняет администратор, основание («по каким кампаниям и за какой период») обязательно. Изначально пусто: цифры вносит агентство.
- **Медиаплан** — период, комиссия агентства (процент от медиабюджета и (или) фиксированная часть в месяц, без НДС), НДС, при желании конверсия в продажу и средний чек. Каналы с закупкой кликов (CPC) или показов (CPM), канал из нормативов добавляется одним выбором. Показы, клики, лиды, CPL, итог к оплате, выручка и ДРР считаются на лету.
- **Сценарии** — «+ сценарий» копирует текущий, внизу сравнение.
- **Скачать Excel** — в фирменном стиле агентства, как рабочие медиапланы: шапка с логотипом (пока его файла нет — подпись SOROKA), бирюзовые заголовки и итоги, рамки, ₽ и %. Колонки для интернет-магазина: площадка, таргетинг, клики, CPC, стоимость без и с НДС, CR1, корзины, CPA, CR2, продажи, CPS, средний чек, выручка, ДРР; одна площадка на несколько сегментов — объединённой ячейкой. Листы «Сводка», по листу на сценарий и «Допущения» (период, комиссия, НДС, средний чек — меняете, пересчитывается всё). Рядом с формулами записаны готовые значения, поэтому цифры видны и в защищённом просмотре Excel.
- **В презентацию** — два слайда (прогноз на период и таблица по каналам) в новую презентацию «Медиаплан» или в конец существующей.

### Задачи

Устроены как в YouGile: **проект → доски → колонки → задачи**.

- **Проекты** — список слева: каждый клиент в работе — проект, плюс «Общие задачи» для внутренних дел команды. Красная точка — есть просроченные, число — открытые задачи. «+» — новый проект (клиент). Раздел открывается на последнем проекте.
- **Доски** — вкладки внутри проекта: например, «Трафик», «Контент», «База знаний по проекту». «+ Доска» создаёт новую с колонками по умолчанию; в меню «⋮» у вкладки — переименовать, сдвинуть, удалить (пустую).
- **Колонки** — свои у каждой доски: название, цвет, порядок («⋮» → «Изменить», «Сдвинуть»), «+ Колонка» в конце доски. Отметка «Задачи в этой колонке — выполнены» — для «Готово»: такие задачи не считаются открытыми и просроченными. Карточки перетаскиваются между колонками; «+ Добавить задачу» — под заголовком колонки.
- **Стикеры на карточке** — срок с временем по Москве («7 окт. к 13:00»; без времени — до конца дня; просроченный — красный), важность (низкая, средняя, высокая, критичная) и ответственный. Ставятся прямо с карточки: щелчок по стикеру — выбор. Круг слева от названия — отметить задачу выполненной.
- **Фильтры** — «Мои», исполнитель, срок (просрочено, сегодня, на неделе, без срока), важность, поиск.
- **Задача** — проект, доска и колонка, ответственный, срок, важность, описание, комментарии. Переносы, выполнение, смена ответственного, срока и важности сами пишутся в историю.
- **Мои задачи** — все задачи, где вы ответственный, со всех проектов, списком по проектам.
- **Клиенты** — контакты, ответственный, заметки, архив. Из заявки — кнопка «Сделать клиентом» в карточке лида.

При обновлении старые задачи переезжают сами: у каждого проекта появляется доска «Задачи» с колонками «К выполнению», «В работе», «На проверке», «Готово», а «Срочно» становится важностью «Высокая».

### Календарь

- **Неделя и список.** Клик по пустому месту в сетке — новая встреча на это время; фильтр «Мои».
- **Встреча:**
  - тема, дата и время по Москве, формат (онлайн, офис, звонок), клиент, гости, участники из команды, повестка;
  - «Создать Zoom» или «Создать Телемост» — ссылка появляется сразу. Для Zoom есть отдельная ссылка организатора — её клиенту не отправляют;
  - «Скопировать приглашение» — готовый текст для клиента: тема, время по Москве, ссылка, повестка.
- **Напоминания в Telegram.** За сутки, за час, за 15 минут — как отмечено во встрече. В 9:00 приходит план на день: встречи и задачи со сроком, включая просроченные. Каждый подключает свой Telegram: «Учётная запись» → «Подключить Telegram» → в боте нажать «Запустить».
- **Подписка на календарь.** «Учётная запись» → «Получить ссылку для подписки». Яндекс Календарь: «Подписаться на календарь» → «По ссылке»; Google: «Другие календари» → «Добавить по URL». Ссылка личная.
- **В карточке клиента** — ближайшие встречи и «Назначить встречу».

### ИИ-помощник

- **«Собрать с ИИ»** в «Создать документ»: что готовим (КП, стратегия, отчёт, презентация агентства), заявка, бриф, объём. Через минуту открывается черновик в редакторе.
- **Меню «ИИ» у слайда:** сократить, сделать яснее, убедительнее, исправить ошибки, заметки докладчика, своя просьба. «Вернуть как было» отменяет правку.
- **«Сократить с ИИ»** — прямо у ошибки проверки «текст не помещается».
- **Правила зашиты в код, а не только в подсказку модели:**
  - цифры, которых не было в брифе или заявке, заменяются на `[заполнить: цифра]` — проверка не выпустит документ, пока человек не впишет настоящие;
  - значения KPI, источник и период данных ИИ не меняет;
  - кейсы не отмечаются проверенными;
  - название клиента, имена, телефоны и почта в модель не уходят — вместо них метки, подстановка уже на сервере.
- Журнал запросов к ИИ хранится в базе (`ai_log`): кто, какое действие, объём — без текстов.

### Квалификатор

- **Лиды** — список с фильтрами (период, рейтинг, статус, канал, поиск по компании и контактам), выгрузка в Excel.
- **Воронка** — канбан по статусам: Новый → В работе → КП отправлено → Сделка / Отказ / Спам. Карточки перетаскиваются.
- **Карточка лида** — почему такой рейтинг, все ответы, источник и UTM, статус, ответственный, комментарий, история изменений.
- **Сводка** — лиды по дням с разбивкой по рейтингу, доля горячих, сколько дошли до конца опроса и на каком вопросе уходят.
- **Тест** — тестовый опрос в виджете и в Telegram. Тестовые лиды помечаются, не смешиваются с рабочими и не уходят менеджерам и в CRM; их карточки можно получать в отдельный чат (`TELEGRAM_TEST_CHAT_ID`).

**Вход** — по логину и паролю. Логины выдаёт администратор в разделе **«Сотрудники»**:

- «Создать доступ» — логин (латиница или e-mail), имя, роль. Пароль генерируется автоматически и показывается один раз, есть кнопка «Скопировать логин и пароль».
- «Сбросить пароль» — новый случайный пароль; старый сразу перестаёт работать, сотрудник выходит со всех устройств.
- «Отключить» — доступ закрывается сразу. Последнего администратора отключить или понизить нельзя.
- Роли: **администратор** управляет сотрудниками, **менеджер** работает с лидами.
- Свой пароль каждый меняет сам: клик по имени в правом верхнем углу.

То же из консоли сервера: `docker compose exec app node scripts/admin.js list | add <логин> <имя> [--admin] | passwd <логин> | role <логин> admin|manager | disable <логин> | enable <логин>`.

Вход через Яндекс ID — по желанию: если задать `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET` (приложение на [oauth.yandex.ru](https://oauth.yandex.ru/client/new), Redirect URI `https://ДОМЕН/admin/auth/yandex/callback`, доступы «Адрес электронной почты» и «Логин, имя и фамилия»), на странице входа появится кнопка. Пускаются сотрудники, у которых логином заведена их почта, или все с доменом из `ADMIN_ALLOWED_DOMAINS`.

## Развёртывание

Нужен сервер в РФ (152-ФЗ) с Ubuntu 22.04/24.04, 2–4 ГБ памяти, и домен с A-записью на IP сервера.

```bash
git clone https://github.com/banifaci13-sketch/kvalificator.git && cd kvalificator
sudo bash deploy/install.sh
```

Установщик ставит Docker, спрашивает настройки (домен, почту для админки, Telegram, Яндекс ID), запускает квалификатор за Caddy с автоматическим HTTPS, создаёт первого сотрудника и печатает его пароль, настраивает ежедневный бэкап базы (14 копий в `data/backups`) и проверяет настройки.

- Если на сервере уже есть nginx с другими сайтами, установщик предложит работать через него: добавит отдельный конфиг `kvalificator.conf` (прокси на `127.0.0.1:APP_PORT`, по умолчанию 3100), проверит его `nginx -t` до перезагрузки и выпустит сертификат через certbot. Другие сайты не затрагиваются. Если на сервере больше ничего нет — HTTPS обслуживает Caddy в Docker.
- Обновление: `sudo bash deploy/update.sh` (сначала бэкап, потом `git pull` и перезапуск).
- Docker Hub с российских серверов недоступен — образы берутся с зеркала `mirror.gcr.io`. Другое зеркало: `NODE_IMAGE` и `CADDY_IMAGE` в `.env`.
- Репозиторий приватный: для `git clone` на сервере нужен токен GitHub с доступом только на чтение или deploy key.

Без Docker: Node.js 22.13+, `npm ci --omit=dev`, `npm start` под systemd и любой обратный прокси с HTTPS.

## Подключение сервисов

Ключи вписываются в `.env` на сервере (`nano /opt/kvalificator/.env`), затем `bash deploy/update.sh`. Без ключа соответствующие кнопки просто не показываются или подсказывают, что сервис не подключён.

- **YandexGPT** (рекомендуется: данные остаются в России). В [Yandex Cloud](https://console.yandex.cloud):
  1. создайте каталог и сервисный аккаунт с ролью `ai.languageModels.user`;
  2. создайте для этого аккаунта API-ключ;
  3. впишите `YANDEX_GPT_API_KEY` и `YANDEX_GPT_FOLDER_ID` (id каталога).
- **Claude** — вместо YandexGPT: `ANTHROPIC_API_KEY`. API Anthropic недоступен с серверов в России.
- **Zoom.** [marketplace.zoom.us](https://marketplace.zoom.us) → Develop → Build App → Server-to-Server OAuth, права на создание встреч (`meeting:write`). Впишите `ZOOM_ACCOUNT_ID`, `ZOOM_CLIENT_ID`, `ZOOM_CLIENT_SECRET` и `ZOOM_USER` — e-mail пользователя Zoom, на которого создаются встречи.
- **Яндекс Телемост** (API доступен организациям Яндекс 360 для бизнеса):
  1. [oauth.yandex.ru](https://oauth.yandex.ru/client/new) → приложение с правом `telemost-api:conferences.create`;
  2. получите токен администратора организации: `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>`;
  3. впишите его в `TELEMOST_TOKEN`.
- **Telegram для напоминаний** — тот же бот, что у квалификатора (`TELEGRAM_BOT_TOKEN`). Каждый сотрудник подключает его в своей учётной записи.

## Что нужно от агентства

- **Ссылка на политику обработки ПДн** — в `PRIVACY_POLICY_URL`.
- **Логотип.** Оригинальные файлы (SVG или PNG): полный логотип для светлого и тёмного фона и знак для аватара виджета — в `brand/assets/logo/` (см. README там). Пока вместо логотипа — текстовая подпись.
- **Брендбук.** Точные цвета и шрифты: сейчас стиль предварительный, документы об этом предупреждают при проверке.
- **Нормативы по каналам** — в разделе «Медиапланы» → «Нормативы».
- **Ориентиры по бюджету для каждой услуги** — в `budgetHints` в `config/scenario.json`.
- **Проверка правил оценки.** Нужно проверить баллы и список звёздных брендов в `config/scoring.json`. Сейчас это первая версия по таблице «Этапы продаж».
