- ошибки фоновых операций (только в логах контейнера).

## 5. Безопасность (проверено 13–14.10.2026)

- **Доступ без входа.** Без входа закрыты все 112 маршрутов API. Тест обходит их без cookie и с поддельной cookie.
  Проверка выполняется в `onRequest` — до разбора тела и приёма файлов.
- **Сессии.** Cookie `httpOnly`, `SameSite=Strict`, `Secure` (при HTTPS), путь `/admin`. В базе хранится только
  sha256 токена. У отключённого сотрудника сессия недействительна сразу.
- **Пароли.** Хранятся как scrypt. Не больше 10 попыток входа за 15 минут с одного IP; поддельная cookie лимит не
  обходит. В Docker включён `TRUST_PROXY`, поэтому IP берётся от nginx.
- **CSRF.** `SameSite=Strict` и изменение данных только JSON-запросами. CORS для `/admin` не открыт.
- **CSP кабинета.** Скрипты и стили только свои, без inline; `frame-ancestors 'none'`.
- **XSS.** Интерфейс выводит пользовательские данные только как текст; `innerHTML` есть только в виджете,
  со статичной разметкой.
- **IDOR.**
  - Чаты и их файлы доступны только участникам, администратору тоже нет.
  - Файл открывается, если он свой, прикреплён к задаче, клиенту или новости, или лежит в чате, где вы участник.
  - Деньги — только по своим клиентам.
- **SSRF.** Сервер обращается только к фиксированным адресам: Telegram, Yandex Cloud, Zoom, Телемост,
  Яндекс OAuth, вебхук CRM и таблица вопросов из `.env`. Ссылки из новостей сервер не открывает.
  Chromium блокирует любые внешние запросы.
- **Секреты.** Только в `.env` (он в `.gitignore`). В истории git токенов не найдено. Ключи на фронтенд не уходят:
  `/admin/api/integrations` отдаёт только «подключено / нет».
- **Контейнер.** Работает от пользователя `node`, порт слушает только на `127.0.0.1`. В лог-драйвере есть
  ротация (10 МБ × 5).
- **Остаточные риски:**
  - prompt injection через данные, попадающие в подсказку модели (раздел 2);
  - бэкапы на том же диске и без файлов;
  - нет журнала действий: кто удалил документ или медиаплан.

## 6. Открытые решения (нельзя решить по коду)

1. **Видимость клиентов.** Сейчас все сотрудники видят всех клиентов, задачи, заявки и документы; деньги — только
   свои. Нужно ли ограничивать специалистов «своими» клиентами? От этого зависят контекст ассистента и
   KPI-дашборд.
2. **Доступ к Директу.** Есть ли агентский аккаунт Директа (доступ к клиентам через `Client-Login`) или к каждому
   клиенту отдельно? Нужна заявка на доступ к API Директа от имени агентства: её рассматривает Яндекс.
3. **Метрика.** Чей логин владеет счётчиками или имеет к ним гостевой доступ? Какие цели считаются лидом?
4. **Резервные копии вне сервера.** Куда их класть (Yandex Object Storage, второй VPS в РФ, диск руководителя)?
   Кто хранит ключ шифрования? Какие допустимы RPO (сколько данных можно потерять) и RTO (как быстро нужно
   восстановиться)?
5. **ПДн.** Есть ли утверждённое положение об обработке персональных данных и согласие сотрудников на хранение
   переписки?
6. **Маржинальность.** Кому её показывать? Есть ли данные о себестоимости часа?
7. **Сервер.** Какие ресурсы (CPU, RAM, диск) и какой реальный размер `data/` на проде? Это нужно для оценки
   бэкапов и Chromium.
