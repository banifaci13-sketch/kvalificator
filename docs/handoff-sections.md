# Копия кабинета: Задачи, Календарь, Документы, Сотрудники

Инструкция для разработчика или ИИ-ассистента (Claude в другом чате), который разворачивает копию кабинета
«Ассистент» Soroka Marketing на другом сайте. Нужны только четыре раздела: **Задачи, Календарь, Документы,
Сотрудники**. Остальные разделы (квалификатор заявок, медиапланы, новости и т. д.) в коде остаются, но в меню
не показываются — их выключает одна настройка `ADMIN_SECTIONS`.

> Почему не вырезать лишний код: разделы связаны (вход и роли, сотрудники, уведомления, ассистент, файлы,
> общая база). Удаление модулей ломает связи и требует переписывать тесты. Настройка безопаснее: та же
> проверенная программа (270+ автотестов), лишнее просто не видно.

## Что получит пользователь

**Задачи** — проекты по клиентам и «Общие задачи», доски со своими колонками (как в YouGile), карточка задачи:
исполнитель, срок со временем, важность, чек-лист, вложения, комментарии, повторяющиеся задачи, «Мои задачи»,
клиенты (карточка клиента с файлами), оплаты по клиентам с напоминаниями. Регламенты → чек-листы задач.

**Календарь** — неделя и список, встречи онлайн / в офисе / звонок, участники из команды, гости клиента,
повестка; ссылка Zoom или Телемост одной кнопкой; регулярные встречи (каждый день, по будням, по дням недели,
раз в две недели, раз в месяц) с правкой «только эту / эту и следующие»; напоминания и план на день в личный
Telegram; подписка в Яндекс/Google Календаре; итоги встречи → задачи исполнителям.

**Документы** — КП, презентации, отчёты, брифы по шаблонам в фирменном стиле; редактор слайдов с превью;
проверка перед выгрузкой; PDF и PPTX; «Собрать с ИИ» из текста брифа (нужен ключ ИИ).

**Сотрудники** (только администратор) — сотрудники и роли, приглашения, сброс пароля; вкладки «Подключения»
(какие сервисы настроены) и «Состояние» (база, бэкапы, фоновые задачи).

Плюс общее: вход по логину и паролю (или Яндекс ID), уведомления в кабинете, светлая и тёмная тема,
мобильная версия, ассистент в боковой панели (команды текстом: «поставь задачу…», «встреча завтра в 15…»).

## Стек

- Node.js 22, Fastify 5, SQLite (встроенный `node:sqlite`), фронтенд без сборки (чистый JS).
- Docker Compose; HTTPS — Caddy или уже установленный nginx (установщик спросит).
- Chromium в контейнере — для PDF документов.
- Данные: `data/` (база, файлы, выгрузки), бэкап каждую ночь + проверка восстановления.

## Развёртывание на сервере (Ubuntu/Debian, root)

1. Направить домен на сервер: A-запись, например `work.example.ru` → IP сервера.
2. Скопировать проект на сервер в `/opt/<имя>` (архив или `git clone`).
3. Запустить установщик и ответить на вопросы (домен, первый администратор):
   ```bash
   cd /opt/<имя> && bash deploy/install.sh
   ```
   Если на сервере уже работает nginx с другими сайтами — выбрать вариант 1 («работать через ваш nginx»),
   **не отключать nginx**.
4. В `.env` добавить строку и перезапустить:
   ```
   ADMIN_SECTIONS=tasks,calendar,docs,staff
   ```
   ```bash
   docker compose up -d
   ```
   Можно добавить `templates` — раздел управления шаблонами документов (в «Документах» шаблоны доступны и так).
5. Обновление после правок кода: `bash deploy/update.sh` (делает бэкап, пересобирает, перезапускает).

Формат `.env`: каждая строка строго `НАЗВАНИЕ=значение`, без пробелов вокруг `=`. Файл `.env` с ключами —
только на сервере, в репозиторий не коммитить.

## Настройки `.env` для этих разделов

| Что | Переменные | Без них |
|---|---|---|
| Адрес кабинета | `DOMAIN`, `PUBLIC_URL` (ставит установщик) | — |
| Первый администратор | `ADMIN_EMAIL`, `ADMIN_PASSWORD` (только при первом запуске) | войти нельзя |
| Разделы в меню | `ADMIN_SECTIONS=tasks,calendar,docs,staff` | видны все разделы |
| Напоминания о встречах и план дня в Telegram | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` (бот от @BotFather) | календарь работает, напоминаний нет |
| Zoom одной кнопкой | `ZOOM_ACCOUNT_ID`, `ZOOM_CLIENT_ID`, `ZOOM_CLIENT_SECRET`, `ZOOM_USER` | ссылку вставляют вручную |
| Телемост одной кнопкой | `TELEMOST_TOKEN` | ссылку вставляют вручную |
| ИИ: «Собрать с ИИ», ассистент | `YANDEX_GPT_API_KEY`, `YANDEX_GPT_FOLDER_ID` (или `AI_PROVIDER` + ключ другого провайдера) | всё работает без ИИ-функций |
| Вход через Яндекс ID | `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, `ADMIN_ALLOWED_DOMAINS` | вход по логину и паролю |

Квалификатор заявок в копии не нужен: его переменные (`TELEGRAM_MANAGER_CHAT_ID`, `LEAD_WEBHOOK_URL`, сценарий)
не заполнять, виджет `widget.js` на сайт не ставить — без виджета заявок не будет. `TELEGRAM_BOT_ENABLED`
не трогать: бот нужен, чтобы сотрудник привязал свой Telegram («Учётная запись» → «Подключить Telegram»).

## Фирменный стиль другого сайта

Сейчас в копии — стиль и логотип Soroka Marketing. Для другого бренда:

1. `brand/brand.config.json` — название, цвета, шрифты (единый источник), затем `npm run brand:sync`.
2. Логотип — **только оригинальный файл** от владельца бренда (PNG/SVG с прозрачным фоном) в
   `brand/assets/logo/`, в `brand.config.json` → `logo` указать файлы и их sha256 (`npm run brand:sync`
   покажет). **Логотип не рисовать и не генерировать.**
3. Шаблоны документов — `templates/decks/*.json` (КП, отчёты, брифы); названия и тексты — под новый бренд.

## Правила (как в исходном проекте)

- Ключи и пароли — только в `.env` на сервере; репозиторий может быть публичным.
- Персональные данные — на сервере в РФ; в ИИ уходят только обезличенные данные (это уже заложено в код).
- Внешние подключения и опасные действия (рассылки, записи во внешние системы) — только после согласования
  с владельцем.
- Данные с сервера Soroka (папка `data/`) в копию **не переносить**: там сотрудники, клиенты, переписка.
  Копия стартует с пустой базой.

## Проверка после установки

1. Открыть `https://<домен>/admin/`, войти первым администратором.
2. В меню — только Задачи, Календарь, Документы, Сотрудники (и шестерёнка порядка меню).
3. «Сотрудники» → добавить сотрудников; «Подключения» — видно, что настроено.
4. «Учётная запись» → «Подключить Telegram» → в боте «Запустить» — проверить напоминание о тестовой встрече.
5. «Документы» → «Новый документ» → выгрузить PDF (проверяет Chromium в контейнере).

## Где что в коде

| Раздел | Сервер | Интерфейс |
|---|---|---|
| Задачи, клиенты, оплаты | `src/crm/` (в т. ч. `money.js`), `src/admin/crm-routes.js` | `admin/tasks.js`, `admin/money.js` |
| Календарь | `src/calendar/` (встречи, серии, напоминания, Zoom/Телемост), `src/admin/calendar-routes.js` | `admin/calendar.js` |
| Документы | `src/docs/`, `src/admin/docs-routes.js`, `templates/decks/` | `admin/docs.js` |
| Сотрудники, вход | `src/admin/auth.js`, `src/admin/routes.js` | `admin/admin.js` (`renderStaff`), `admin/system.js` |
| Меню и выключение разделов | `ADMIN_SECTIONS` → `src/config.js` | `admin/admin.js` (`sectionAllowed`, `NAV`) |
| База и миграции | `src/storage/db.js` (схема создаётся сама при запуске) | — |

Тесты: `npm test`. Подробное описание всех функций — `docs/functionality.md`, общая справка — `README.md`.
